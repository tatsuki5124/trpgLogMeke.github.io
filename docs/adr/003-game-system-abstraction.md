# ADR-003: ゲームシステムの抽象化

**状態**: 採用

## 判断

ゲームシステム固有のロジック（ダイス判定、技能成長、初期技能値）を `LogmakeSystem` インターフェース経由で抽象化し、`src/logmake/systems/` に配置する。

## 理由

- CoC 6th と 7th でダイス判定ロジック・技能値・成長判定が異なる。
- エモクロア対応を予定しており、システム追加時にパーサーや UI を変更せずに済む設計が必要。
- `ParsedLog → DiceEvent → SystemAnalysis → OutputModel` のパイプラインを維持し、システム固有の処理をアダプターに閉じ込める。

## 代替案

- **条件分岐で対応**: `if (system === 'coc6')` のような分岐をロジック各所に入れる方法。システム追加のたびに散在する分岐が増え、保守困難になる。
- **プラグイン方式**: 動的ロードは静的サイトには過剰。ビルド時に全システムをバンドルすれば十分。
