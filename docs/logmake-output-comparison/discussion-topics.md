# ログ出力表示 議論項目メモ

ログ出力 HTML の見え方について議論を続けるための論点整理。
ここに書いた内容は最終決定ではなく、比較 HTML を見ながら検討するための材料。

視覚要素の仕様詳細は [visual-spec.md](./visual-spec.md) に別途記録している。

---

## 前提

- 主読者は卓参加者。
- 最優先は「会話追跡性」と「本文可読性」。
- production の出力仕様はまだ確定させず、まず比較 HTML で見比べる。
- 縦書き・PDF は次段階。現時点の議論は主に横書き HTML。

---

## 現在の比較対象

`pnpm logmake:compare-output` で `docs/logmake-output-comparison/` に生成する。

- `speaker-after-line.html`: 名前の後ろから短いキャラクター色ラインを伸ばす案。
- `speaker-body-guide.html`: 本文左側に薄いキャラクター色ガイドを引く案。
- `candidate-combined.html`: 名前下線を軸にした統合候補。
- `*-dark.html`: 各案のダークモード確認用。

一度整理のため、次の単体比較は生成対象から外した。

- `legacy.html` / `candidate-colored-body.html` / `current.html` / `conservative.html` / `body-base.html` / `speaker-underline.html`

## 確定事項

- **本文色はキャラクター色なし（標準色）。** `candidate-colored-body` 案は除外。
- **タブブロックの背景色は必須。** 左ボーダーのみには戻さない。
- **情報タイトルの横位置は `left: .5rem`。** 比較用・production 共通。
- **発言境界マーカーは名前下線（`::after border-block-end`）を軸にする。**
  名前後ろライン（speaker-after-line）は縦書きでのレイアウト崩壊リスクがあり脱落。
  本文左ガイド（speaker-body-guide）は「範囲の強調」であり「境界の明示」には弱く脱落。

## 発言境界と名前マーカー

**確定: 名前下線（`::after` で `border-block-end: 2px solid var(--log-speaker-color)`）を採用。**

経緯:
- 名前後ろライン（`speaker-after-line`）は `inline-flex` + `clamp` 固定長のため、縦書きモードで意図しないレイアウトになるリスクが最も高かった。
- 本文左ガイド（`speaker-body-guide`）は `color-mix` を使い発言範囲を示せるが、「境界の明示」には弱い。
- 名前下線は名前ラベルに直接付くため「発言者識別」の手がかりが最小コストで届く。

未決:

- 名前下線の opacity（現在 `.48`）の最終値。
- 縦書き時: `border-block-end` は縦書きで inline-end 方向（文字の右側）に変わる。
  縦書きモード時は `border-inline-end` に切り替えるか、下線を無効化するかを決める必要がある。
- リンクと誤認されないかどうか（スマホでのタップ誘発）の最終確認。

## 場面タイトルの強調

論点:

- 現状の `h3.log-scene` は `margin-block-start: 2rem`。キャラクター発言（`1.7rem`）との差は約 `0.3rem`（≒ 5px）にとどまる。スクロール中に知覚できる差ではなく、「あの場面はどこ？」の再読時に場面転換点を素早く見つけられない。

- 強調に「背景色帯」を使うことはできない。タブ（グレー薄塗り）・情報ブロック（白背景）・成功/失敗ハイライト（水色/赤帯）で背景色はすでに意味付けされており、第4の背景色要素を加えると視覚言語が崩れる。

検討材料:

- **上余白拡大のみ（2rem → 3〜3.5rem）**: 最小変更で縦書き・印刷に安全。ただし差を大きくしすぎると頻繁なシーン切り替えのセッションで間延びする。
- **上ボーダー + 余白拡大**: `border-block-start: 1px solid var(--log-speaker-color)` を薄い opacity で入れる。線は「場所探し」に機能し、背景色を使わないため視覚文法と衝突しない。印刷時も細線として残る。縦書き時は `border-block-start` が inline-start 方向に変わるため横書き専用として使うか、縦書き時は無効化が必要。
- **水平線（`::before`）**: スクロール中の場所探しに最も効くが、縦書き時に物理的な向きが変わり崩れる可能性がある。

未決:

- 強調手段の最終決定（余白のみか、上ボーダーを加えるか）。
- 上ボーダーを採用する場合の色・opacity・縦書き対応方針。
- 余白の最終値（現在 `2rem`、候補 `3〜3.5rem`）。

## 場面・地の文・KP/GM

論点:

- CCFOLIA のログデータ上、KP/GM/話者なしは他のキャラクターと構造的に同一（名前・色・テキスト）。
  「地の文」として特別扱いする根拠はデータにはなく、比較案でのみ手動オーバーライドしている。
- 一方で KP の発言は「状況提示・演出」であり PC の「行動宣言」とは情報の性質が異なる。
  視覚的に区別することで「今これは演出か行動か」の判断コストが下がる利点がある。
- 「最優先は会話追跡性」という前提のもとでは、名前を非表示にする現行 narration スタイルは矛盾を含む。

検討材料:

- **通常話者扱い（名前あり・speaker スタイル）**: データ上の実態に忠実。会話追跡性を損なわない。ただし場面転換が PC 発言と同列に埋もれる。
- **名前なし narration（現行比較案）**: KP/GM/話者なしの名前を消して地の文として表示。会話追跡性を壊す。「最優先」前提と矛盾。
- **`scene-named`（中間案）**: 名前を残しつつ、本文を narrationColor・名前を低 opacity（`0.55` 程度）で表示する。会話追跡性を保ちながら「これは演出」という視覚的非対称性も出せる。
- 自動検出するなら「KP」「GM」「話者なし」の完全一致リストが最も確実。部分一致・頻度ベースは「KP という名の PC」などで誤判定を起こす。
- ユーザーが `CharacterConfig.style` を変更して `speaker` に戻せる逃げ道を設けることで、自動検出の精度が低くても許容できる。

未決:

- `scene-named` 中間案を正式な選択肢として採用するか。
- 採用するなら `CharacterStyle` の型と `renderVariant` の設計をどうするか（`buildOutputModel` で解決するか）。
- 自動検出リストをユーザーが編集できる UI を作るか。
- KP/GM を「名前あり表示（speaker スタイル）」にユーザーが戻せる UI を作るか。
- `CharacterStyle` の型から `scene` を将来除外するか、ユーザー設定名として残すか。

## 見出し階層と HTML 構造

論点:

- production は `.box5` / `.char` / `.KP` / `.bbb` などの旧 Vue 版クラス名をそのまま引き継いでいる。
  比較案は `log-section` / `log-entry--speaker` など BEM 的な意味論的クラス体系に刷新済み。
- `<span class="log-speaker">` はキャラクター名をラベルとして示すが、セマンティクス上は `<strong>` が正確（見出しではなくラベル）。
- 情報ブロックの `<h4 class="log-info-title">` は見出し要素だが、100 発言あれば h4 が多数生成されアウトラインを汚染する。情報タイトルは `<p><strong>` で十分。
- 補助タブは `<section>` より `<aside>` が意味論的に正確（補助的な内容であるため）。
- 比較案の `title="雑談"` は tooltip 用属性であり、`aria-label` の代替にならない。

検討材料:

- 推奨構造骨格（現時点の合意として）:
  ```html
  <main class="log-frame">
    <section class="log-section log-section--primary" aria-labelledby="...">
      <h2 id="..." class="log-section-title">メイン</h2>  <!-- 視覚非表示 -->
      <strong class="log-speaker">探索者A</strong>        <!-- span → strong -->
      <h3 class="log-scene">場面：地下室前</h3>
      <p class="log-info-title"><strong>技能名</strong></p>  <!-- h4 → p+strong -->
    </section>
    <aside class="log-section log-section--tab ..." aria-label="雑談タブ">
      <!-- section → aside、title → aria-label -->
    </aside>
  </main>
  ```

未決:

- キャラクター名を `<span>` から `<strong>` に変更するタイミング（比較案先行か production 同時か）。
- 情報タイトル `<h4>` → `<p><strong>` の変更タイミング。
- 補助タブ `<section>` → `<aside>` への変更タイミング。
- `title` → `aria-label` の修正タイミング。

## ログ本文全体の囲い・色ブロック

論点:

- `.log-frame` の `border: double 5px frameColor` は「配布物らしさ」を出す意図だが、
  `frameColor` と `log-frame` の背景色の組み合わせによっては二重枠がほとんど視認されない。
- タブ左ボーダー・情報枠・名前下線が加わると、全体枠は「4層目の装飾」になる。

検討材料:

- 廃止した場合: `border: none` または記述削除。レイアウトへの影響は最小限。
  外側の frameColor 背景が log-frame の白背景と接するフラットな見た目になる。
- 維持する場合: `double` を `solid` に変えて視認性を上げるか、frameColor より濃い色を使うか。

未決:

- 廃止するか、形式を変えて維持するか。

## 情報ブロック

**確定: 情報タイトルの横位置は `left: .5rem`。**

### タブ内での浮き問題

情報ブロックの背景色は `back`（白）のため、補助タブ（グレー薄塗り）の内側では情報ブロックが「浮いて」見える副作用がある。これはタイトルの浮き出し効果（枠線を背景色で隠す）の構造的な副作用で、意図したものではない。

未決:

- タブ内での情報ブロックの背景を透明化するか（浮き出しタイトル効果と衝突するため要検討）。
- 情報枠の色・枠線太さ・角丸を現状から変更するか。

## 情報タブのピン留め問題

論点:

- CCFOLIA の「情報」タブはチャット内容のピン留め（メモ帳）として使うユーザーが多い。
  その場合、同じ内容をメインタブにも流す運用になり、配布 HTML にメインと情報で重複したコンテンツが出力される。
- 現状、「情報」タブは `isPrimaryTab` でメインと同等に扱われ、補助タブのグレー背景・左ボーダーが付かない。
  これが「情報タブを特別扱いする」かどうかの設計判断と絡んでいる。

検討材料:

- **重複省略オプション**: 情報タブとメインタブで内容が一致するエントリを自動検出して省略する（複雑・誤判定リスクあり）。
- **表示オプション化**: 情報タブの内容を配布 HTML に含めるかどうかをユーザーが選択できるようにする。
- **情報タブの同等化再検討**: 情報タブをメインと同等ではなく、「雑談」などの補助タブと同等に扱うかどうかを再設計する。

未決:

- 情報タブをメインと同等扱いのまま維持するか、補助タブ同等に変更するか。
- 重複コンテンツの扱いをオプションとして提供するか。
- オプション化するなら設定のデフォルトをどうするか。

## 成功/失敗ハイライト

- 成功/失敗マーキングがダークモードで強すぎる、または薄すぎないか。
- 比較ではライトは元の `#7fbfff` / `#ff7f7f` を維持。ダークのみ `rgba(...)` で半透明にしている。
- 透明度を下げすぎるとマーキングが埋もれる。

未決:

- production では現在文字列置換でダーク用 gradient に切り替えているが、正式に highlight 色を生成する設計にするか。

## 地の文の余白・色の最終値

論点:

- `.log-entry--narration` は `margin: .65rem 1rem .65rem .5rem` で、キャラクター発言（`1.7rem`）より大幅に詰まっている。
  発言の流れに溶け込む設計として意図しているが、現在は調整中。
- narrationColor（`#555555` / ダーク `#b8b8b8`）と余白の組み合わせが最適かどうか未決。
- 場面タイトル上余白との関係（場面タイトル h3 `margin-block-start: 2rem` に対し、直前の地の文 `margin-block-end: .65rem`）も整合性の検討が必要。

未決:

- narration の margin の最終値。
- 場面タイトルとの余白バランス（場面タイトル強調の議論と連動）。

## 縦書き・PDF

- 縦書きはすでに `writing-mode: vertical-rl` 分岐が production に実装済み。
- 名前下線（`border-block-end`）は縦書きで inline-end 方向（文字の右）に変わる。
- 上ボーダー（`border-block-start`）は縦書きで inline-start 方向（文字の左）に変わる。
- PDF 対応は未着手。縦書き・PDF に横書き HTML の考え方をどう持ち込むかは次段階の議論。

## 次の議論で決めたいこと

優先度の高い順。

1. **場面タイトルの強調手段**: 上余白のみか、上ボーダー（`border-block-start`）を加えるか。余白の最終値。
2. **地の文・KP/GM の扱い**: `scene-named`（名前薄め + 地の文色）を採用するか。通常話者のままか。
3. **情報タブのピン留め問題**: 情報タブをメイン同等のまま維持するか。重複コンテンツをオプションで扱うか。
4. **HTML 構造刷新の適用タイミング**: `<strong>` 化・`<aside>` 化・`aria-label` 修正・情報タイトルの `<h4>` → `<p><strong>` をいつ production に反映するか。
5. **ログ全体の枠線**: `border: double 5px` を廃止するか維持するか。
6. **発言境界（名前下線）の縦書き対応**: `border-block-end` を縦書き時にどう扱うか。
7. **ダーク時成功/失敗ハイライトの最終 opacity**。
8. **本文色の設定化**: 将来的にオプションにするか。するならデフォルト・ダーク時の扱いをどうするか。
9. **KP/GM を名前あり表示に戻せる UI**: 設けるかどうか。
10. **縦書き・PDF への展開**: 同じ考え方をどう持ち込むか。
