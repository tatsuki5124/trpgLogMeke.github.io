# ログ出力表示 議論項目メモ

このメモは、ログ出力HTMLの見え方について別チャットで議論を続けるための論点整理です。
ここに書いた内容は最終決定ではなく、比較HTMLを見ながら検討するための材料です。

## 前提

- 主読者は卓参加者。
- 最優先は「会話追跡性」と「本文可読性」。
- production の出力仕様はまだ確定させず、まず比較HTMLで見比べる。
- 縦書き/PDFは次段階。現時点の議論は主に横書きHTML。
- 旧表示と本文キャラクター色案は生成対象から外し、名前のみキャラクター色・本文標準色を前提に発言境界マーカーの案を比較する。

## 現在の比較対象

`pnpm logmake:compare-output` で `docs/logmake-output-comparison/` に生成する。

- `speaker-after-line.html`: 名前の後ろから短いキャラクター色ラインを伸ばす案。
- `speaker-body-guide.html`: 本文左側に薄いキャラクター色ガイドを引く案。
- `candidate-combined.html`: 名前下線を軸にした統合候補。
- `*-dark.html`: 各案のダークモード確認用。

一度整理のため、次の単体比較は生成対象から外した。

- `legacy.html`: 旧表示寄せ。人物本文にもキャラクター色を使う。
- `candidate-colored-body.html`: 統合候補を土台に本文もキャラクター色にした案。本文色の比較に使ったが、除外が確定。
- `current.html`
- `conservative.html`
- `body-base.html`
- `speaker-underline.html`

## 本文色

**決定: 本文は標準色（キャラクター色なし）**

- 人物発言の本文は標準文字色を使う。名前のみキャラクター色にする。
- `candidate-colored-body` 案は比較対象から除外。
- ユーザー設定化（`標準色 / キャラクター色`切り替え）は将来検討。

未決:

- 設定化する場合の設定名・デフォルト値・縦書き適用。

## 発言境界と名前マーカー

論点:

- 本文を標準色にしたとき、誰の発言かをどう追いやすくするか。
  （もしくは、本文色をキャラクター色にする場合も、発言境界をどう示すか。）
- 名前下線、名前後ろライン、本文左ガイドのどれが読みやすいか。
- マーカーを足しすぎると、補助タブや情報枠と視覚記号が衝突しないか。

検討材料:

- 名前後ろラインは、名前から横に伸びるため話者識別には効くが、横方向の記号量が増える。
- 名前下線は見やすい可能性があるが、リンク風に見えないか確認が必要。
- 本文左ガイドは発言ブロックの範囲を示しやすいが、本文がインデントされるためログ全体の左位置が揺れやすい。
- インデントを揃える、やたらとブラさない、という方針は重要。

未決:

- 統合候補の名前マーカーを下線で進めるか。
- 本文左ガイドを採用候補に残すか。
- マーカーなしでも余白設計だけで足りるか。

## 場面・地の文・KP/GM

論点:

- `地の文` と `場面` をユーザーに分けて見せるべきか。
- GUI上も内部的にも `場面` にまとめてよいか。
- KP/GM/空話者は、場面名なしの `場面` として扱うのが分かりやすいか。
- 地の文をより場面っぽく見せるために、見出しやマーカー、区切り線、インデント、背景色などを足すべきか。

検討材料:

- UIの言い回しとしては `地の文` より `場面` の方が分かりやすい可能性がある。
- 現状は KP/GM/空話者を `displayName: null` の scene/narration 系として扱っている。
- 場面名ありは `<h3 class="log-scene">...</h3>` で出す。
- KP/GM/空話者は見出しなしで、本文だけを同じ流れに置く。
- KP/GM/空話者は、インデントを深くせず、話者名と同じ左位置に寄せる方が自然。

未決:

- `CharacterStyle` は `character | item | scene` のままでよいか。
- 内部に `renderVariant: 'speaker' | 'info' | 'scene' | 'narration'` を持たせるべきか。
- KPをユーザー操作で「名前あり」に戻せるようにするか。
- 場面タイトルは h3 のままでよいか、h2に上げるべきか。

## 見出し階層とHTML構造

論点:

- 場面タイトルは h3 で十分か、h2の方がログ上では見やすいか。
- キャラクター発言の名前も見出し要素にするべきか。
- 発言単位を section にするべきか。

検討材料:

- `h3` として出しているなら、CSSで本文サイズに潰さない。
- 見出し要素を増やすと、見た目だけでなくHTMLアウトラインにも影響する。
- キャラクター発言を h3/section 化すると、ログ全体の意味構造は強くなるが、1発言ごとの見出しが多すぎる可能性がある。
- 見た目だけを整えたいなら、まずはクラスとCSSで調整する方が影響範囲は狭い。

未決:

- ログ全体のアウトラインをどう設計するか。
- 場面タイトルを h2 にするなら、タブセクション見出しとの関係をどうするか。
- キャラクター名を見出しにするか、単なるラベルに留めるか。

## ログ本文全体の囲い・色ブロック

論点:

- ヘッダーはさておき、色のブロックでログ本文を囲うこと自体が見やすいのか。
- より読みやすいログ形式があるのではないか。

検討材料:

- 現状は `log-frame` が背景色と枠を持ち、本文全体を囲う。
- 旧表示も `box5` で本文全体を囲っていた。
- 色ブロックは「配布物らしさ」「ログ全体のまとまり」を出せる。
- 一方で、長文ログでは囲い・背景・タブ色・情報枠・マーカーが重なり、情報量が増えすぎる可能性がある。

未決:

- 本文全体の枠を残すか、もっと紙面に近いフラットな形式にするか。
- タブブロックや情報ブロック以外の装飾をどこまで減らすか。
- ライト/ダークで同じ構造を使うか。

## タブブロック

**決定: タブブロックの背景色は必須**

- 補助タブは背景色 + 左ボーダーで範囲を示す。背景色なしには戻さない。

未決:

- タブ名ラベルの位置・濃さ・有無をどうするか。

## 情報ブロック

**決定: 情報タイトル位置は `left: .5rem`**

- 横書き情報タイトルは `left: .5rem` を正とする（比較用も `.5rem` に統一済み）。

未決:

- info枠の色を production で変更するか。
- 情報ブロックの角丸や枠線太さを現状維持するか。

## 成功/失敗ハイライト

論点:

- 成功/失敗マーキングがダークモードで強すぎる、または薄すぎないか。
- ライトモードは元の強さのままでよいか。

検討材料:

- 比較ではライトは元の `#7fbfff` / `#ff7f7f` を維持。
- ダークのみ `rgba(...)` で少し薄くしている。
- 透明度を下げすぎるとマーキングが埋もれる。
- 本文標準色にした場合も、成功/失敗が見える必要がある。

未決:

- ダーク時の最終 opacity。
- production では文字列置換ではなく、正式に highlight 色を生成する設計にするか。

## ダークモード

論点:

- デフォルト色のキャラクター本文がダークモードで読みにくくならないか。
- 名前だけ色を付ける方が安全ではないか。

検討材料:

- キャラクター色はログ由来で、ダーク背景に対するコントラストが保証されない。
- 名前だけなら色の問題が限定される。
- 本文をキャラクター色にする設定を入れるなら、ダークモード時のリスクを説明する必要がある。

未決:

- ダークモードでキャラクター本文色を許可するか。
- 設定化する場合のデフォルトをどうするか。
